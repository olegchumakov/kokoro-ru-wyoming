# Kokoro Wyoming TTS

Русский сервер синтеза речи на базе [Kokoro](https://github.com/hexgrad/kokoro) и проекта [`zaakirio/kokoro-ru`](https://huggingface.co/zaakirio/kokoro-ru).

Сервер предоставляет интерфейс Wyoming TTS для Home Assistant и поддерживает потоковое воспроизведение речи.

## Возможности

- Русский Kokoro TTS
- Протокол Wyoming
- Потоковая генерация TTS
- Немедленная отправка первого готового аудиочанка
- Короткая PCM-тиша при отставании генератора
- Автоматическая синхронизация голосов и моделей из `zaakirio/kokoro-ru`
- В сервере нет логики, привязанной к конкретным голосам
- В сервере нет жёсткого сопоставления моделей
- PyTorch на CPU
- Переносимый каталог проекта
- Автоматическое создание локального Python-окружения
- Необязательная установка systemd-сервиса

## Требования

- Linux
- Доступ в интернет для PyPI и Hugging Face
- Права на установку необходимых системных пакетов во время настройки

Скрипт установки сам определяет версию Python, совместимую с текущим пакетом Kokoro, и не содержит жёстко заданной версии Python. При необходимости он также сам устанавливает системные зависимости, например `espeak-ng`.

## Установка

Клонируйте репозиторий:

```bash
git clone https://github.com/olegchumakov/kokoro-ru-wyoming.git
cd kokoro-wyoming
```

Запустите настройку окружения:

```bash
./setup.sh
```

Скрипт:

1. Находит Python, совместимый с текущим пакетом Kokoro.
2. Создаёт `.venv/` внутри каталога проекта.
3. Устанавливает Kokoro и его заявленные Python-зависимости.
4. Устанавливает CPU-сборку PyTorch.
5. Устанавливает Wyoming.
6. При необходимости устанавливает системные зависимости.
7. Запускает `install.py`.
8. Проверяет готовое окружение.

Для установки необязательного systemd-сервиса:

```bash
./install_service.sh
```

Запуск:

```bash
systemctl start kokoro-wyoming
```

Проверка:

```bash
systemctl status kokoro-wyoming
```

Просмотр логов:

```bash
journalctl -u kokoro-wyoming -f
```

При успешной загрузке в логе появляются примерно такие строки:

```text
Kokoro warmup complete
Listening on tcp://0.0.0.0:10200
```

## Обновление голосов и моделей

Запустите:

```bash
.venv/bin/python install.py
```

`install.py` читает настроенный upstream-репозиторий и синхронизирует runtime-файлы, голоса и checkpoint-модели.

Он автоматически:

- скачивает актуальный `config.json`;
- скачивает актуальный `ru_g2p.py`;
- определяет актуальный список голосов;
- определяет checkpoint для каждого голоса;
- скачивает только необходимые checkpoint-модели;
- скачивает соответствующие voice-файлы;
- обновляет `wyoming.json`;
- сохраняет локальные настройки голосов, например `enabled` и пользовательские descriptions;
- удаляет устаревшие голоса и управляемые локальные файлы моделей/голосов.

Появление нового голоса upstream не требует изменения `wyoming_server.py`.

## Конфигурация

Основной файл конфигурации — `wyoming.json`.

В нём находятся настройки приложения:

- upstream-репозиторий;
- URI Wyoming-сервера;
- формат аудио;
- параметры streaming;
- количество потоков PyTorch;
- уровень логирования;
- метаданные TTS;
- голос по умолчанию;
- локальные пути runtime-файлов.

Сопоставление голосов и checkpoint-моделей поддерживается `install.py`.

### Пример: изменить голос по умолчанию

```json
"default_voice": "masha"
```

### Пример: изменить длительность тишины при underrun

```json
"silence_seconds": 0.2
```

### Пример: изменить адрес Wyoming

```json
"uri": "tcp://0.0.0.0:10200"
```

## Архитектура

Upstream-файлы намеренно не хранятся в Git-репозитории.

```text
Git-репозиторий
    |
    +-- setup.sh
    +-- install.py
    +-- wyoming_server.py
    +-- wyoming.json
    +-- install_service.sh
    |
    v
Локальная установка
    |
    +-- .venv/
    +-- config.json
    +-- ru_g2p.py
    +-- models/
    +-- voices/
```

Сопоставление голосов и моделей полностью generic:

```text
voice -> voice file -> checkpoint
```

В сервере нет специальных случаев для отдельных имён голосов.

## Ручной запуск

После установки:

```bash
.venv/bin/python wyoming_server.py
```

## Перемещение проекта

Каталог проекта переносим.

`wyoming_server.py` определяет свой базовый каталог по расположению самого скрипта, а относительные пути из `wyoming.json` разрешаются относительно него.

Если проект был перемещён и используется systemd-сервис, пересоздайте unit:

```bash
./install_service.sh
```

Unit-файл использует фактический каталог проекта и локальный `.venv`; фиксированного пути установки нет.

## Лицензия

Этот репозиторий содержит Wyoming-сервер и скрипты установки и конфигурации.

Kokoro, runtime-файлы, модели и голоса `zaakirio/kokoro-ru` предоставляются соответствующими upstream-проектами и регулируются их собственными лицензиями и условиями использования.
